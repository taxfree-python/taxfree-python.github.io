## Attention

causal softmax attention の 1 head の出力は、位置 $t$ の query に対して

$$
a_{t,i}=\frac{\exp(q_t^\top k_i/\sqrt{d_k})}
{\sum_{j\le t}\exp(q_t^\top k_j/\sqrt{d_k})},
\qquad
o_t=\sum_{i\le t}a_{t,i}v_i
$$

と書けます。過去の token ごとに KV を保存しておくので、後から来た query に応じて、その時点で必要な位置を参照できます。その代わり、系列長を $N$ とすると KV cache は $N$ に比例して増えていきます。

GDN と KDA は、過去の情報を固定サイズの状態 $S_t\in\mathbb{R}^{d_k\times d_v}$ に保持します。入力のたびに $S_t$ を更新し、$o_t=S_t^\top q_t$ として読み出します。つまり、後からどんな query が来るかを知らないまま、有限の状態に何を残すかを決めなければなりません。

{{< block name="memory" >}}

図 1. 共通の token 列と、各方式が保存するもの。softmax attention は token ごとの KV を保持し、GDN / KDA は固定サイズの状態を更新する。上下の対応は token の位置を表す (projection は方式ごとに異なる)。

Qwen3.8-Flash-Next は GDN と global softmax attention を、Kimi K3 は KDA と Gated Multi-head Latent Attention (Gated MLA) を組み合わせています（Qwen3.8-Flash-Next は full attention で学習を進め、continued pretraining の段階で full attention の層を Qwen Sparse Attention (QSA) に置き換えます。その際、まず full attention の注意分布を QSA の indexer に蒸留してから、sparse な注意での学習に移ります）。再帰的な層の状態は固定サイズですが、softmax attention の層では系列長に応じて KV cache が増えます ([Qwen Team, 2026, pp. 4, 6][qwen-2026]; [Kimi Team, 2026, pp. 3–5][kimi-2026])。

## Gated DeltaNet

加算による更新 (additive update) では、associative memory を

$$
S_t=S_{t-1}+\beta_t k_t v_t^\top
$$

として更新します。この場合、同じ key への書き込みも足し合わされ続けます。これに対して delta rule は、現在の状態から読み出した value と新しい value の差を使って補正します ([Schlag et al., 2021][schlag-2021])。

$$
S_t=S_{t-1}
+\beta_t k_t\left(v_t-S_{t-1}^\top k_t\right)^\top.
$$

GDN は、この補正の前にスカラー gate $\alpha_t$ による減衰を加えます ([Yang et al., 2025][yang-2025])。

$$
\begin{aligned}
\widetilde S_t&=\alpha_t S_{t-1},\\
e_t&=v_t-\widetilde S_t^\top k_t,\\
S_t&=\widetilde S_t+\beta_t k_t e_t^\top.
\end{aligned}
$$

$\alpha_t,\beta_t\in(0,1)$ は、head ごとに入力から決まる gate です。減衰は状態全体にかかり、delta rule は現在の key の方向だけを補正します。GDN はこの 2 つを組み合わせることで、不要になった文脈を消しつつ、個々の key–value の対応を書き換えられるように設計されています ([Yang et al., 2025, §3.1–3.2][yang-2025])。

Qwen の GDN では、正規化した residual stream の入力を $x_t\in\mathbb{R}^d$ とし、学習される線形射影 $W_q,W_k,W_v$ と causal ShortConv から各 head の $q_t,k_t,v_t$ を作ります。

$$
\begin{aligned}
c_t^a&=\operatorname{ShortConv}_a\!\left((W_a x_i)_{i\le t}\right)_t,
\quad a\in\{q,k,v\},\\
q_t&=\operatorname{L2Norm}\!\left(\operatorname{SiLU}(c_t^q)\right),\\
k_t&=\operatorname{L2Norm}\!\left(\operatorname{SiLU}(c_t^k)\right),\\
v_t&=\operatorname{SiLU}(c_t^v).
\end{aligned}
$$

ここでは 1 head 分だけを書いており、$W_q,W_k\in\mathbb{R}^{d_k\times d}$、$W_v\in\mathbb{R}^{d_v\times d}$ です。ShortConv は channel ごとに独立にかかる短い causal convolution で、添字 $t$ はその出力の位置を表します。また Qwen の GDN では、各 head から読み出した出力に RMSNorm と sigmoid output gate をかけます ([Qwen Team, 2026, p. 4][qwen-2026])。以下では、この出力側の処理より前の状態更新だけを扱います。

### Online learning

GDN を提案した [Yang et al. (2025), §3.1, Table 1][yang-2025] は、fast weight matrix の更新を正則化付きの online optimization として定式化しています。Kimi Linear の §2.2 でも、DeltaNet を online gradient descent として、GDN をそれに weight decay を加えたものとして明示的に導出しています ([Kimi Team, 2025, §2.2][kimi-2025])。

現在の token から作った $k_t,v_t$ を固定し、$S$ に対する損失を

$$
\ell_t(S)=\frac12\left\|S^\top k_t-v_t\right\|_2^2
$$

と置くと、勾配は

$$
\nabla_S\ell_t(S)=k_t(S^\top k_t-v_t)^\top
$$

です。GDN の delta update は

$$
S_t=\widetilde S_t-\beta_t\nabla_S\ell_t(\widetilde S_t)
$$

となり、線形回帰の online gradient descent に一致します。$S$ が回帰モデルの重み、$k_t$ が入力、$v_t$ が regression target、$\beta_t$ が learning rate に当たります。なお、ここでは $\alpha_t$ による減衰を先にかけ、減衰後の $\widetilde S_t$ で勾配を評価しています。減衰前の $S_{t-1}$ で勾配を評価してから weight decay を加える更新とは、順序が異なります。

ここでいう online learning は、系列を token の順に読みながら $S$ を更新していくことを指します。この状態更新は、事前学習でも推論でも forward の中で行われます。事前学習では、next-token prediction の損失の勾配を状態更新を通して流し、projection や gate などのパラメータを学習します。推論ではそれらのパラメータを固定したまま、入力に応じて $S$ だけを更新します。$v_t$ は現在の入力から作られるので、この更新に正解の次 token は要りません。

表 1. GDN における outer loop と inner loop。

| | 更新対象 | 目的関数 |
|---|---|---|
| Outer loop | Projection、gate、MLP などの学習パラメータ | Next-token prediction |
| Inner loop | 各 head の状態 $S$ | key から value への回帰 |

このように、状態そのものをモデルの重みとみなし、forward の中で自己教師あり損失を使って更新する構成は、Test-Time Training (TTT) と共通しています。TTT では、この内側のモデルを線形モデルや MLP とし、inner loop の入力と target を作る射影も outer loop で学習します ([Sun et al., 2024, §2.1–2.3][sun-2024])。

### 局所損失と出力

更新式から予測できる振る舞いを整理しておきます。$\|k_t\|_2=1$ のとき、更新直後の残差は

$$
v_t-S_t^\top k_t=(1-\beta_t)e_t
$$

なので、同じ回帰損失は

$$
\ell_t(S_t)=(1-\beta_t)^2\ell_t(\widetilde S_t)
$$

になります。$\beta_t=1$ という極限では、その key に対する読み出しは $v_t$ に一致します。

また、delta update の大きさ (Frobenius norm) と、固定した任意の query $q$ への影響は

$$
\begin{aligned}
\|S_t-\widetilde S_t\|_F&=\beta_t\|e_t\|_2,\\
(S_t-\widetilde S_t)^\top q&=\beta_t(k_t^\top q)e_t
\end{aligned}
$$

です。$k_t$ と直交する query には delta update の影響が及ばず、$k_t$ と重なる方向にだけ補正が伝わります。

ただし、これらはあくまで潜在表現の上での回帰の話です。同じ事実を言い換えて与えても、学習された key / value が同じ関係を表すとは限りません。回帰の残差が減ることが文章中の情報の更新に対応しているかどうかは、実際のモデルで確かめる必要があります。

## Kimi Delta Attention

KDA は、GDN のスカラーによる減衰を key channel ごとの減衰に拡張します ([Kimi Team, 2025][kimi-2025])。$D_t=\operatorname{Diag}(\boldsymbol\alpha_t)$ とすると、更新は

$$
\begin{aligned}
\widetilde S_t&=D_tS_{t-1},\\
S_t&=\widetilde S_t+
\beta_t k_t\left(v_t-\widetilde S_t^\top k_t\right)^\top\\
&=(I-\beta_t k_tk_t^\top)D_tS_{t-1}
+\beta_t k_tv_t^\top
\end{aligned}
$$

となります。$D_t=\alpha_t I$ とすれば GDN と一致します。inner loop の回帰問題と delta update は GDN と共通で、KDA でも

$$
S_t=\widetilde S_t-\beta_t\nabla_S\ell_t(\widetilde S_t)
$$

です。違うのは、勾配 step の前にかける減衰が、GDN ではスカラーの $\alpha_t I$、KDA では channel ごとの $D_t$ である点です。

一般には $(I-\beta_t k_tk_t^\top)D_t\ne D_t(I-\beta_t k_tk_t^\top)$ なので、減衰と delta update の順序は交換できません。また、$k_tk_t^\top$ を通して channel 間の結合が生じます。

各 channel の decay logit を $z$、head ごとの learned log-scale を $A_h$ とすると、log-decay $g=\log\alpha$ の parameterization は次のように変わります。

$$
\begin{aligned}
g_{\text{Kimi Linear}}(z)&=-e^{A_h}\operatorname{Softplus}(z),\\
g_{\text{Kimi K3}}(z)&=-5\,\sigma(e^{A_h}z).
\end{aligned}
$$

Kimi K3 の log-decay は $-5<g<0$、retention factor は $e^{-5}<\alpha<1$ です。そのため 16 token の区間では累積 log-decay が $(-80,0)$ に収まり、chunkwise 計算で使う累積減衰の逆数は $e^{80}$ 未満になります ([Kimi Team, 2026, p. 5, Eq. 5][kimi-2026])。

{{< block name="decay-functions" >}}

図 3. $A_h=0$ での log-decay $g=\log\alpha$。破線は $g=-5$。Kimi K3 では log-decay に下限があり、retention factor は $\alpha>e^{-5}$ となる。学習後の logit の分布ではなく、同じ $z$ を入れたときの関数の形を比べている。

channel ごとに減衰率を持てるからといって、各 channel が特定の事実に対応するとは限りません。減衰の自由度が増えることと、意味的に独立した情報を選んで消せることは別の話です。

## Olmo Hybrid を使った観察

ここからは学習済みモデルで、前半で整理した状態更新が実際にどう使われているかを調べます。問いは 3 つです。1 つ目は、state が前半で見た key から value への回帰として働いているか。2 つ目は、その回帰の損失に passage の内容がどれだけ表れるか。3 つ目は、passage の書き込み、とくに答えに当たる token の書き込みを止めたときに、回答の尤度がどれだけ変わるかです。

対象とする `allenai/Olmo-Hybrid-Instruct-SFT-7B` は、GDN と softmax attention を 3:1 の比率で積んだモデルです (Qwen3.8-Flash-Next の GDN と full attention、Kimi K3 の KDA と Gated MLA も同じ 3:1 です)。以下では、そのうち 24 層の GDN を計測します ([Merrill et al., 2026][merrill-2026]; [Qwen Team, 2026, p. 1][qwen-2026]; [Kimi Team, 2026, p. 4][kimi-2026])。

表 2. Checkpoint と実行条件 ([config][olmo-config])。

| 項目 | 条件 |
|---|---|
| Checkpoint | Olmo Hybrid Instruct SFT 7B / [15ec262d91de][olmo-config] |
| Layers | GDN 24 層、softmax attention 8 層 |
| GDN の head | 30 head、key / value の次元は 96 / 192 |
| Precision | BF16 weights、FP32 recurrent state |
| Software | PyTorch 2.10.0a0 (NGC コンテナ `nvcr.io/nvidia/pytorch:25.11-py3`)、Transformers 5.8.1 |
| GPU | DGX Spark / NVIDIA GB10 |

Olmo Hybrid Instruct SFT 7B の GDN は負の固有値 (negative eigenvalues) を許す拡張を使っていて (上で紹介した GDN では $\alpha_t,\beta_t\in(0,1)$)、$\beta_t\in(0,2)$ です。$\beta_t>1$ では、更新後の回帰残差の符号が反転することがあります。また、前節では $\|k_t\|_2=1$ を仮定しましたが、測定ではこの checkpoint が実際に出力する gate の値 $\alpha_t,\beta_t$ と key $k_t$ をそのまま使います。

### 文書 QA

まず、文書を読んで答える QA の基本性能として、Stanford Question Answering Dataset (SQuAD) v1.1 の dev set 全 10,570 問を評価します。データは Wikipedia の 48 記事から取った passage と、それぞれに対応する質問からなります。入力では passage の後に質問を置き、batch size 32 の greedy decoding で最大 1,024 token まで生成しました。SQuAD 自体には文書を与えない評価条件はないので、比較のために passage を取り除いた「文書なし」の条件を独自に加えています ([Rajpurkar et al., 2016][rajpurkar-2016])。

採点は SQuAD 公式の exact match (EM) と token F1 に従います。小文字にそろえ、句読点と英語の冠詞を取り除き、空白を整えたうえで、EM では回答全体が一致するか、token F1 では空白で区切った単語がどれだけ重なるかを測ります。正答の annotation が複数ある設問では、それぞれに対するスコアの最大値を取ります。例えば正答 `thousands` に対する `thousands of years` は EM = 0、token F1 = 0.5 です。この採点では、同義語や単数形・複数形は別物として扱われます ([公式の採点コード][squad-evaluation])。

表 3. SQuAD dev 全 10,570 問の結果。回答全体を採点し、EM・平均 token F1 は % で示す。「上限到達」は、EOS を出す前に 1,024 token に達した件数。

| 条件 | Exact match | Mean token F1 | 上限到達 |
|---|---:|---:|---:|
| 元の文書 | 75.62 | 87.97 | 0 / 10,570 |
| 文書なし | 2.29 | 9.09 | 7 / 10,570 |

文書なしの 7 問は、質問や `The short answer is:` などを繰り返し続けて生成上限に達したもので、表では保存された出力をそのまま採点しています。文書なしの条件でも「与えた文書だけを使う」という指示は残しているので、答えられなくても、モデルの知識不足とは限りません。

### State 解析の設問

state の解析には、SQuAD v1.1 の dev set から、1 つの passage と 3 つの質問からなる組を規則で選びました。以下では、この 3 問を「組」と呼びます。各組は、同じ事実を言い換えて問う 2 問 (Q1、Q2) と、同じ passage の別の事実を問う 1 問 (Q3) からなります。同じ事実を 2 通りに問うことで、特定の質問文にだけ現れる効果と、言い換えても残る効果を切り分けます。Q3 は、効果が passage 全体に及ぶのか、対象の事実に限られるのかを比べるための対照です。

Q1 と Q2 では、すべての正答 annotation が passage 中の同じ 1 箇所を指しています。その正答に当たる token の位置の集合を $\mathcal{A}$ とし、区間 $\mathcal{A}$ と呼びます。

後の節の activation patching では、区間 $\mathcal{A}$ を別の語に置き換えた passage (以下、反実仮想の passage) を使います。そのため、置き換えができる組だけを選びます。置き換えは [Longpre et al. (2021)][longpre-2021] の corpus substitution に倣い、SQuAD dev のほかの記事の質問の正答から、同じ種類の語を選びます。ただし patching では、元の passage と反実仮想の passage で token の位置がそろっている必要があるので、token の数が同じ語に限ります。

表 4. 組の選び方と、各段階で残った組の数。

| 段階 | 条件 | 残った組 |
|---|---|---:|
| 1 | Q1・Q2：同じ段落の 2 問で、すべての正答 annotation が同じ 1 区間を指し、その文字列が passage に 1 回だけ出る | 152 |
| 2 | Q3：同じ段落の質問で、すべての正答 annotation が区間 $\mathcal{A}$ と重ならず、その文字列が passage に 1 回だけ出る (候補が複数あれば、区間 $\mathcal{A}$ から最も遠いもの) | 151 |
| 3 | 区間 $\mathcal{A}$ が固有表現抽出で人物・日付・数・組織・場所のどれかになる | 107 |
| 4 | 3 問の質問文に、置き換える語が含まれない | 91 |
| 5 | 置き換えの候補がある (同じ種類、同じ token 数、日付と数は書式と桁数も同じ、ほかの記事の正答) | 71 |
| 6 | 1 つの段落から 1 組だけ | 54 |
| 7 | 反実仮想の passage に矛盾がなく、文法が正しく、語の種類が合っている | 31 |

固有表現抽出には spaCy の `en_core_web_trf` を使い、種類は Longpre et al. と同じ 5 種類にまとめました。置き換える語は、段階 5 の候補から乱数の種を固定して選びます。人物の姓のように、区間 $\mathcal{A}$ と同じものを指す語が passage のほかの場所にも出てくる場合は、同じ置き換えでそろえます。段階 7 は反実仮想の passage を読んで判定し、patching の結果を見る前に組を固定しました。

最終的な 31 組 (93 問) の答えの種類は、人物 15、数 7、日付 6、組織 3 です。場所を答えとする組は段階 7 で残りませんでした (国の位置に都市が入るなど、置き換えで場所の粒度がずれたため)。記事は 9 本で、そのうち Super_Bowl_50 が 17 組を占めます。

### State と局所回帰損失の測り方

各設問について、全 24 層の GDN・全 30 head で、モデルが次の token に渡す recurrent state を取り出しました。layer の番号は 0 始まりで、3、7、11、15、19、23、27、31 は softmax attention の層です。計測用の処理を入れても、最終 logits は入れない場合と全 token で bitwise に一致しました。

局所回帰損失は、delta update 前の state で測ります。質問の token の位置の集合を $\mathcal{Q}$ とし、質問の各 token を読む時点で、同じ $k_t,v_t$ に対する $\ell_t(\widetilde S_t)$ を比べます。比べる相手の state を $\widetilde S'_t$ として、設問・layer ごとに $\mathcal{Q}$ と全 head について損失を足し合わせてから比を取ります。

$$
R=
\frac{\sum_{t\in\mathcal{Q}}\sum_h\ell_{t,h}(\widetilde S_{t,h})}
{\sum_{t\in\mathcal{Q}}\sum_h\ell_{t,h}(\widetilde S'_{t,h})}.
$$

$R<1$ なら、通常の state のほうが比べる相手よりも現在の $v_t$ をよく再現しています。比べる相手には次の 4 つを使います。

- $S=0$：何も書き込まれていない state。$\ell_t(0)=\frac12\lVert v_t\rVert_2^2$ です。
- 質問より前の書き込みを除いた state：その layer だけで、質問より前のすべての token (chat template、passage、`Question:` など) について $\beta_t=0$ とします。
- passage の書き込みを除いた state：その layer だけで、passage の token について $\beta_t=0$ とします。
- 区間 $\mathcal{A}$ の書き込みを除いた state：その layer だけで、$t\in\mathcal{A}$ について $\beta_t=0$ とします。

$\beta_t=0$ にしても $\alpha_t$ による decay は残し、質問の token 自身の更新もそのままにします。layer $L$ の $k_t,v_t,\alpha_t,\beta_t$ はそれより下の層だけで決まるので、layer $L$ だけへの介入は layer $L$ の入力を変えません。実際に、介入した forward で得た state と、通常の forward で得た $k_t,v_t,\alpha_t,\beta_t$ から更新式を計算し直した state は、全条件で相対誤差 $5.0\times10^{-8}$ 以内で一致しました。

### State は回帰として働いているか

$S=0$ と比べると、30 問 × 24 層の 720 条件のうち 719 条件で $R<1$ でした。中央値は 0.465、10–90 パーセンタイルは 0.154–0.763 です。唯一の例外は `dust-satellite` の片方の質問に対する layer 2 で、1.025 でした。学習済みモデルでも、state の読み出し $\widetilde S_t^\top k_t$ はゼロベクトルよりも現在の $v_t$ に近く、中央値では $\lVert v_t\rVert_2^2$ の半分ほどを再現しています。前半で見た「状態更新は key から value への回帰」という読み方は、学習済みモデルでも成り立っています。

ただし、$S=0$ は何も覚えていない state との比較です。この結果だけでは、state のどの書き込みがこの改善を生んでいるのかは分かりません。

### 局所回帰損失は passage を反映しているか

比べる相手を書き込みを除いた state にすると、$R$ は 1 に近づきます。

表 5. 局所回帰損失の比 $R$ (30 問 × 24 層の 720 条件)。

| 比べる相手 | 中央値 | 10–90 パーセンタイル | $R<1$ の条件 |
|---|---:|---:|---:|
| $S=0$ | 0.465 | 0.154–0.763 | 719 / 720 |
| 質問より前の書き込みを除く | 0.811 | 0.606–0.952 | 720 / 720 |
| passage の書き込みを除く | 0.932 | 0.874–0.979 | 706 / 720 |
| 区間 $\mathcal{A}$ の書き込みを除く | 0.99986 | 0.99830–1.00044 | 513 / 720 |

{{< block name="local-loss" >}}

図 5. layer ごとの $R$ の中央値 (30 問)。比べる相手ごとに 1 本の線で示す。

$S=0$ との差の大部分は、質問より前の書き込みを除いても残ります。passage の書き込みを除いたときの変化はさらに小さく、区間 $\mathcal{A}$ の書き込みを除いたときの $R$ は 0.979–1.007 の範囲に収まります。同じ事実を問う質問と別の事実を問う質問でも、区間 $\mathcal{A}$ を除いたときの $R$ の中央値は 0.99986 と 0.99987 で差がありません。質問の token での回帰の改善は、主に質問の token 自身がそれまでに書き込んだ内容から来ていて、passage、とくに答えに当たる token の書き込みはほとんど寄与していません。

layer 別に見ると、深い layer では $S=0$ との比が小さく (layer 25 で 0.105)、質問より前の書き込みを除いたときの比も下がります (layer 25 で 0.511)。深い layer では質問より前の文脈の寄与が大きくなりますが、それでも layer 24 以降で passage の書き込みだけを除いたときの比は 0.91–0.98 です。

この損失は、現在の token から作った latent value をどれだけ再現できるかを測るものです。質問への正答を直接測るものではありません。次の節では、回答の尤度で同じ書き込みの寄与を調べます。

### 回答は passage の書き込みに依存しているか

指定した SQuAD の正答 token 列を $a_r=(a_{r,1},\ldots,a_{r,M})$ とし、teacher forcing で

$$
\log p_\theta(a_r\mid x)
=\sum_{m=1}^{M}\log p_\theta(a_{r,m}\mid x,a_{r,<m})
$$

を計算します。各時点の最終 logits に `log_softmax` をかけ、正答 token の成分を取り出して足し合わせます。介入した条件と通常の条件の差を $\Delta\log p$ とします。$\exp(\Delta\log p)$ は正答列の尤度比なので、例えば $\Delta\log p=-\log 2$ は尤度が半分になったことを表します。この測定では正答列を teacher forcing で与えていて、介入した条件で自己回帰生成はしていません。そのため $\Delta\log p$ は正答列をモデルがどれだけ支持するかの変化を表しますが、生成される回答文字列が変わるかどうかまでは分かりません。

1 つの layer だけで passage の書き込みを止めても、$\Delta\log p$ の中央値は 0.0000 nats でした (720 条件、最小は `studio-trailer` の layer 26 の −3.803)。一方、24 層の GDN すべてで同時に passage の書き込みを止めると、30 問すべてで正答列の尤度が下がりました。$\Delta\log p$ の中央値は −6.65 nats で、最も小さい変化でも −1.07 nats です。

{{< block name="passage-removal" >}}

図 6. 24 層の GDN すべてで passage の書き込みを止めたときの、質問ごとの正答列の $\Delta\log p$。

このモデルの softmax attention の 8 層は、passage の token を KV cache から直接読めます。それでも GDN への passage の書き込みを止めると、回答の尤度は大きく下がります。前の節で見たとおり、passage の書き込みは質問の token での局所回帰損失にはあまり表れません。局所回帰損失が小さく変わることは、その書き込みが後で使われていないことを意味しません。

### 答えの書き込み：1 層と全層

ここで確かめたい仮説は、passage を読むときの区間 $\mathcal{A}$ の delta update が対象の事実を state に書き込み、その情報が同じ入力の後半にある質問への回答に使われる、というものです。この仮説が正しければ、区間 $\mathcal{A}$ の書き込みを止めると、独立に評価した 2 つの質問でどちらも同じ正答の尤度が下がり、別の事実を問う質問への影響は相対的に小さくなるはずです。

{{< block name="write-intervention" >}}

図 7. 仮説と介入。各 token は delta update で固定サイズの state $S$ に書き込み、同時に $S$ から読み出す ($o_t=S_t^\top q_t$)。図では passage の書き込みと質問の読み出しだけを描いている。区間 $\mathcal{A}$ の token だけ $\beta=0$ として書き込みを止めると、同じ事実を問う 2 問では正答列の尤度が下がり、別の事実を問う 1 問ではほとんど変わらないと予想される。

介入する layer の集合を $\mathcal{L}$ とし、その全 head について $t\in\mathcal{A}$ のときだけ $\beta_t=0$ にします。$\mathcal{L}$ は 1 つの layer か、24 層の GDN すべてです。

$$
\beta_{t,h}^{(\ell),\mathrm{skip}}=
\begin{cases}
0 & \ell\in\mathcal{L},\ t\in\mathcal{A},\\
\beta_{t,h}^{(\ell)} & \text{otherwise}.
\end{cases}
$$

このとき区間 $\mathcal{A}$ では $S_t^{(\ell)}=\widetilde S_t^{(\ell)}=\alpha_t S_{t-1}^{(\ell)}$ となり、state には decay だけがかかります。重みは固定したままで、hidden state を正解の値に置き換えるような操作はしていません。同じ事実を問う 2 問の $\Delta\log p$ を $\Delta_1,\Delta_2$、別の事実を問う質問の $\Delta\log p$ を $\Delta_c$ として、組ごとに

$$
D=\Delta_c-\frac{\Delta_1+\Delta_2}{2}
$$

を計算します。$D>0$ なら、対象の事実の正答列の尤度のほうが、別の事実の正答列の尤度より下がったことになります。どれだけ差があるかは $D$ の大きさで見ます。書き込みを止めること自体の影響と区別するため、各 passage で区間 $\mathcal{A}$ と同じ長さの対照区間を 1 つ選び、同じ介入をします。対照区間は区間 $\mathcal{A}$ から 4 token 以上離し、3 問のどの正答 annotation とも重ならない位置にしました。

1 つの layer だけで止めた場合、区間 $\mathcal{A}$ と対照区間の $D$ はほとんど区別できません。組 × layer の 240 条件で、区間 $\mathcal{A}$ の $D$ の中央値は 0.0062 nats、対照区間は 0.0016 nats でした ($D>0$ の条件はそれぞれ 144 と 134)。はっきりした例は `studio-trailer` の layer 26 です。この tokenizer では `Jason Bourne` は ` Jason`、` Bour`、`ne` の 3 token に分かれます。同じ事実を問う 2 問の $\Delta\log p$ は −3.421 と −2.515 で、`Gods of Egypt` を問う質問では −0.0036 でした。このような大きな効果は、1 つの layer ではほかにほとんど見られません。

24 層の GDN すべてで同時に止めると、区間 $\mathcal{A}$ の $D$ の中央値は 1.97 nats になり、対照区間の 0.04 nats を大きく上回りました。

図 8. 選んだ組での、質問ごとの正答列の $\Delta\log p$。左は区間 $\mathcal{A}$ の書き込みを 1 つの layer ずつ止めた場合、右の 2 列は 24 層の GDN すべてで同時に止めた場合 (区間 $\mathcal{A}$ と対照区間)。

10 組のうち 6 組 (`studio-trailer`、`tentacle-term`、`statement-attribution`、`dust-satellite`、`highest-court`、`immune-agent-term`) では、同じ事実を問う 2 問の尤度がそろって下がり、別の事実を問う質問の変化はそれよりずっと小さくなりました。この 6 組の多くでは、全層で止めたときの効果が 1 つの layer ずつの効果の和を大きく上回ります。例えば `statement-attribution` では、全層で止めると $D=11.28$ nats ですが、1 つの layer ずつの $D$ の和は −0.03 nats です。どの 1 層を止めても効果がほとんど出ないのに、全層で止めると尤度が大きく下がるので、この事実の情報は複数の layer の state に重ねて書き込まれ、1 つの layer が欠けてもほかの layer で補われていると考えられます。

残りの 4 組 (`emigration-year`、`river-city`、`asset-share`、`chosen-profession`) では、全層で止めても $|\Delta\log p|\le0.16$ nats でした。これらの組では、答えに当たる token の GDN への書き込み以外の経路、例えば関係を述べる周りの token や softmax attention の層が答えを運んでいると考えられます。`asset-share` では対照区間の $D$ (1.42) が区間 $\mathcal{A}$ の $D$ (0.08) より大きく、対照区間がいつも影響のない区間になるとは限りません。

### 限界

- 組は 10 個、質問は 30 問だけです。同じ組の質問どうし、同じ質問の layer どうしは相関しているので、統計的な検定はしていません。
- 対照区間は各 passage に 1 つだけで、固定した規則で選んでいます。`highest-court` では最初の規則で選んだ区間が別の事実の正答の中にあったので、規則に正答との重なりを除く条件を加えて選び直しました。選び直した区間は、その正答のすぐ手前にあります。
- 1 つの layer ずつの実験と全層の実験では batch の構成が違うため、通常条件の $\log p$ がわずかに異なります (例えば `studio-trailer` の Q1 で −1.077 と −1.133)。$\Delta\log p$ は、どちらも同じ batch の中の通常条件との差です。
- 区間 $\mathcal{A}$ は正答の annotation に当たる token だけです。関係を述べる節のほかの token、ShortConv、softmax attention の経路には介入していません。

## まとめ

今回、GDN / KDA を式のレベルまで整理したことで、アーキテクチャのお気持ちが少し分かった気がします。最初は softmax attention の key / value と同じような役割だと思っていましたが、token ごとに KV を残すのではなく、key / value を固定サイズの state への書き込みに使うという捉え方の違いがあることが分かり納得 (ほんとか?)。

state の更新が online での SGD の 1 step に対応していることにも、今回初めて気づきました。単なる recurrent update として眺めていましたが、forward の中で小さな回帰問題を token ごとに解いていると捉えると見え方はおもしろいと思いました。

## 関連研究

recurrent state への書き込みを直接扱った研究に、[Young (2026)][young-2026] の WriteSAE があります。状態への行列更新を rank-one の atom で表し、実際の書き込みを atom に置き換えたときの出力を評価しています。対象は Qwen3.5-0.8B などの学習済みモデルで、複数の layer・head で置き換えを検証しています。今回の介入は特定の区間で更新を止めるだけで、WriteSAE のように更新を意味のある成分に分解して置き換えるものではありません。
